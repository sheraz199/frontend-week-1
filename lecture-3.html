Unboxing HTML

Now that you understand how the internet delivers data, it is time to build what the user actually sees. Today, we begin with the absolute foundation of the web: HyperText Markup Language.

1. The Frontend Trio

Every modern website, no matter how complex, is built using a combination of three core languages. Think of them like the human body:

  • HTML (The Skeleton): Provides the raw structure and content. Without it, you have nothing.
  • CSS (The Skin/Clothes): Provides the visual styling—colors, fonts, and layouts.
  • JavaScript (The Muscle): Provides behavior, logic, and interactivity.

2. What is HTML?

HTML stands for HyperText Markup Language.

It is not a programming language. It cannot do math, and it cannot make decisions. It is a markup language. Its only job is to wrap raw text in "tags" to tell the web browser what that text represents.

Anatomy of an HTML Element 
<!-- Opening Tag -->    <!-- Content -->    <!-- Closing Tag (has a slash) -->
   <h1>                Welcome to Nexus         </h1>

<!-- The browser reads this and says: "Ah, display 'Welcome to Nexus' as a large Heading." -->

3. The Anatomy of an HTML Document

Every HTML file requires a specific "boilerplate" structure to be considered valid by web browsers.

index.html 
<!DOCTYPE html> <!-- Tells the browser we are using HTML5 -->
<html lang="en"> <!-- The root element that wraps everything -->
  
  <head>
    <!-- Metadata: Invisible to the user, important for the browser & SEO -->
    <meta charset="UTF-8">
    <title>My First Website</title>
  </head>
  
  <body>
    <!-- The Body: EVERYTHING the user actually sees goes in here -->
    <h1>Hello World</h1>
    <p>Welcome to my site.</p>
  </body>

</html>

4. Basic Text Formatting

HTML provides specific tags to format text.

  • Headings: Ranging from <h1> (largest/most important) down to <h6> (smallest). You should only ever have one <h1> per page!
  • Paragraphs: The <p> tag is used for blocks of standard text.
  • Emphasis:
    • <strong> makes text bold (and tells screen readers it's important).
    • <em> makes text italicized.

5. HTML5 Semantics (Meaning)

In older versions of HTML, developers wrapped everything in meaningless <div> tags. HTML5 introduced Semantic Tags—tags that actually describe their purpose.

  • <header>: Top area containing logos and navigation.
  • <nav>: A block of navigation links.
  • <main>: The primary content of the page.
  • <section>: A thematic grouping of content.
  • <article>: A standalone piece of content (like a blog post).
  • <footer>: The bottom area containing copyrights and legal links.
Why use Semantics?
1. SEO (Search Engines): Google ranks pages higher if it can easily understand the structure using semantic tags.
2. Accessibility: Screen readers for visually impaired users rely on semantic tags to navigate the page out loud.

6. Links and Images (Attributes)

Tags often need extra instructions called Attributes. They always go inside the opening tag.

Anchor (Link) & Image Tags 
<!-- The Anchor tag (a) creates a link. 
     href = Where it goes. 
     target="_blank" = Opens in a new tab. -->
<a href="https://google.com" target="_blank">Click to visit Google</a>

<!-- The Image tag (img) is self-closing (no </img>).
     src = The path to the image file.
     alt = Text description if the image fails to load (Crucial for SEO). -->
<img src="profile.jpg" alt="A photo of the author smiling" />

7. Structuring Lists

HTML has two primary ways to create lists. Both require the use of <li> (List Item) tags inside a parent container.

Unordered List (Bullet Points)
<ul>
  <li>Milk</li>
  <li>Eggs</li>
  <li>Bread</li>
</ul>
Ordered List (Numbered)
<ol>
  <li>Preheat oven</li>
  <li>Mix ingredients</li>
  <li>Bake for 20 mins</li>
</ol>

8. HTML Tables

Tables are used to display tabular data (like Excel sheets). Never use tables for website layout!

Table Structure 
<table>
  <thead> <!-- Table Header Section -->
    <tr>  <!-- Table Row -->
      <th>Name</th>  <!-- Table Header Cell (Bold by default) -->
      <th>Age</th>
    </tr>
  </thead>
  <tbody> <!-- Table Body Section -->
    <tr>
      <td>Ali</td>   <!-- Table Data Cell -->
      <td>25</td>
    </tr>
  </tbody>
</table>

9. Forms (The Architecture)

Forms are how users send data (like logins or checkouts) back to the server. Everything is wrapped inside a <form> tag.

Basic Form 
<!-- action: where the data goes. method: how it is sent (POST protects data) -->
<form action="/submit-login" method="POST">
  
  <!-- The Label describes the input for screen readers and usability -->
  <label for="userEmail">Email Address:</label>
  
  <!-- The Input. 'id' connects to the label. 'name' is what the server reads -->
  <input type="email" id="userEmail" name="email" required />
  
  <button type="submit">Log In</button>

</form>

10. Form Input Types

HTML5 introduced powerful input types that automatically trigger mobile keyboards (e.g., pulling up the `@` symbol for emails) and handle basic validation.

  • <input type="text">: Standard short text.
  • <input type="password">: Hides characters as `***`.
  • <input type="email">: Requires an `@` symbol.
  • <input type="date">: Opens a native calendar picker.
  • <input type="checkbox">: Multiple selections (e.g., "Select your skills").
  • <input type="radio">: Single selection (e.g., "Choose Male or Female").
  • <textarea></textarea>: Multi-line text for paragraphs/messages.
  • <select>: Creates a dropdown menu using <option> tags.

11. Divs and Spans

Sometimes you need to group elements together strictly for CSS styling, and no semantic tag makes sense. That is when we use non-semantic containers:

<div> (Block-Level)

Acts like a box. It takes up the full width of the screen and forces a line break before and after itself. Used for grouping large sections.
<span> (Inline-Level)

Sits perfectly inside a line of text without causing a line break. Used for styling a single word inside a paragraph.

12. HTML Industry Best Practices

Writing code that simply "works" on your screen is not enough. Professionals write code that is clean, maintainable, and accessible.

  1. Indentation: Always indent child elements inside their parent. Messy code causes bugs.
  2. Lowercase Tags: Always write tags in lowercase (<p>, not <P>).
  3. Proper Nesting: Close tags in the reverse order they were opened.
    Correct: <p><strong>Text</strong></p>
    Wrong: <p><strong>Text</p></strong>
  4. Always use Alt Text: Never write an <img> tag without an alt attribute.
